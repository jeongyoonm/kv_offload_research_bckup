# Prefer free blocks without pending store readers

## Mechanism and scope

GLM 5.3 NVFP4 TP8, unchanged original selector, FP8 KV, 96 GiB GPU KV
per rank, 2,130,300,354,560 aggregate CPU bytes in private mappings. Both
arms use the global GPU reuse fence, optimized provisional preparation,
8 MiB/depth-2 H2D pipeline, early KV submission, the same frozen predictor,
90 ms prediction subtraction and 100 ms setup lead. Only allocation preference
differs. Four separately primed/reset 75-request episodes per arm (300 total)
use 61,440 prompt tokens, 58,368 restored CPU-prefix tokens, one output token
and concurrency 32. This is not a continuous 300-request stream.

The ordinary pool prepends freed uncached blocks. They can remain D2H sources
and be chosen again despite many other free GPU blocks. The candidate selects
other free blocks first and falls back to pending-source blocks when necessary.
It does not reserve extra capacity, change references or retire stores early.
Actual completion and existing source-before-overwrite fences remain authoritative.
The optimization only knows stores already tracked at allocation time.

## Matched results

| Metric | Control | Preference |
| --- | ---: | ---: |
| Mean throughput (requests/s) | 7.7952 | 7.8266 |
| Mean TTFT (ms) | 3519.09 | 3517.08 |
| Mean episode p95 TTFT (ms) | 4659.30 | 4642.76 |
| Compute rounds per episode | 12.50 | 12.00 |
| Inter-compute gaps per episode (ms) | 222.15 | 161.52 |
| Forward-to-GPU-start wait per episode (ms) | 58.25 | 5.81 |
| Recovered opportunities / KV-ready during compute | 91.72% | 92.68% |

Paired geometric throughput change is +0.401%; individual repeats are
+0.305%, +0.843%, +0.485%, and -0.025%. Mean TTFT is essentially unchanged.
These are four descriptive repeats, not a statistical significance claim.
Inter-compute gaps fall 27.3%; forward-to-GPU-start waiting falls 90.0%.

Each arm allocates 72,000 blocks in 150 calls per episode. The control selects
7,536 already-pending source blocks across its four episodes; the candidate
selects zero. The control emits 224 reuse-fence calls across all ranks and
four episodes; the candidate emits zero. Minimum free-pool sizes are 4,436
control and 4,388 candidate, while the largest individual allocation is 912.
The observed conflict is therefore an allocation-order dependency, not a
lack of free GPU blocks in this workload. Repeated scanning costs an additional
2.6-9.4 ms of allocator CPU work per episode; skipped-block counts count repeated
encounters, not unique blocks. Source safety is also preserved by existing
fallback fences if a store becomes known after allocation.

## Decision and evidence

Retain this opt-in fix for the measured reuse stalls, with a modest serving
gain. Retest under a preencoded, synchronized first client wave to reduce
arrival variation, and evaluate matched GPU-resident workloads.

Targeted allocation checks: 4 passed; broader regression: 205 passed. All
serving cells passed exact restored-token accounting, no-GPU-prefix-hit,
no-preemption, one-output-token, frozen-state and all-rank preparation checks.
This preserves the previously documented sparse-selector nondeterminism;
it is not an all-workload model accuracy claim.
